# Kushal Tours & Travels — Website Guide

Welcome to the Kushal Tours & Travels website project.

This document explains the website, its files, how to make common changes,
how to run the website on a computer, and how to publish updates online.

It is written for business owners and users who may not have a technical
background.

---

## 1. About This Website

Kushal Tours & Travels is a responsive business website for a tours and
travels service based in Wakad, Pune, Maharashtra.

The website helps visitors:

- Learn about the company and its travel services.
- Explore available vehicles and fleet options.
- Browse tour packages and popular routes.
- Find the business contact number and location.
- Call the business directly to enquire about a booking.
- View the website on mobile phones, tablets, laptops and desktops.

### How bookings work

The website uses direct contact links for enquiries. Visitors can click
the relevant call or booking link to open their device's calling application.

A booking is confirmed directly with the operator after the trip details
and availability have been agreed.

This project should not be assumed to include an online payment system,
customer login system, booking database or automatic reservation system.

## 2. Important Project Folders

The project uses Next.js, React and TypeScript.

Here is a simple explanation of the main folders:

- `app/` — Website pages and the main site-wide layout.
- `components/` — Reusable parts of the website, such as the header and footer.
- `lib/` — Shared website settings, business details and helper functions.
- `public/` — Images, logos and other static files used by the website.
- `node_modules/` — Installed software packages. Generated by npm.
- `.next/` — Temporary build output generated by Next.js.
- `package.json` — Project information, dependencies and available commands.
- `package-lock.json` — Records the installed dependency versions.
- `tsconfig.json` — TypeScript configuration.
- `next.config.*` — Next.js configuration, if present.
- `app/globals.css` — Global styles and website appearance.
- `README.md` — This guide.

Do not manually edit `node_modules/` or `.next/`. These folders are generated
by the development tools.

Some configuration files may have different names or may not be present.
Only change files that exist in the project.

Reusable website components are stored in `components/`.

Important files include:

- `components/site-footer.tsx`

A component may appear on more than one page. Changing a shared component
can therefore affect multiple pages.

## 5. Where to Change Business Details

The shared business settings are maintained in:

`lib/site.ts`

This is the first file to check when updating the business contact information.

It currently contains settings such as:

- `phoneDisplay` — The phone number displayed to visitors.
- `phoneHref` — The phone number used by telephone links.
- `whatsappNumber` — The number used for WhatsApp links.
- `mapsUrl` — The business location/map link.

### Updating the contact number

1. Open the project folder.
2. Open `lib/site.ts` using a code editor such as Visual Studio Code.
3. Find the relevant setting.
4. Update the number carefully.
5. Save the file.
6. Test the header, homepage booking links, footer and other contact buttons.
7. Test the WhatsApp link separately.

Keep the phone number consistent everywhere.

For Indian telephone links, the number normally includes the country code
`+91`. For WhatsApp links, the number normally uses digits only, including
the country code, without a plus sign or spaces.

Only use the correct, business-approved phone number.

### Updating the business location

Find `mapsUrl` in `lib/site.ts` and replace its value with the correct
Google Maps link. Check that the location link opens the intended business
location after publishing.

## 6. Changing Website Text

The location of the text depends on which page or section contains it.

Examples:

- Homepage headings, descriptions and section content:
  `app/page.tsx`

- About page:
  `app/about/page.tsx`

- Services page:
  `app/services/page.tsx`

- Fleet page:
  `app/fleet/page.tsx`

- Tour packages page:
  `app/tours/page.tsx`

- Footer text and footer navigation:
  `components/site-footer.tsx`

- Header navigation and header buttons:
  `components/site-header.tsx`

### Safe editing rules

- Change only the text that needs to be updated.
- Preserve the surrounding JSX/TSX tags and component structure.
- Do not remove quotation marks, braces or closing tags.
- Do not rename CSS classes unless the associated styling is also updated.
- Do not replace an entire file just to change a sentence.
- Check the website locally before publishing.

If you are unfamiliar with code, make a backup before editing and ask a
developer to review structural changes.

## 7. Replacing Images and Logos

Static images are generally stored in the `public/` folder.

To find an image used by a page:

1. Open the relevant page or component.
2. Search for the image filename or an image path beginning with `/`.
3. Find the corresponding file inside `public/`.
4. Back up the original file.
5. Replace it with the approved image, preferably keeping the same filename
   and file format.
6. Check the result on desktop and mobile.

If the filename or file format changes, update every reference to the image.

### Image recommendations

- Use high-quality, appropriately sized images.
- Avoid extremely large files that slow down the website.
- Use descriptive filenames.
- Preserve the intended subject and composition of the image.
- Check that text remains readable over hero images.
- Check that images are not unexpectedly cropped, stretched or zoomed.

Do not assume every image is controlled by the homepage CSS. Identify the
actual image element and its styling before making changes.

## 8. Changing Website Colours, Buttons and Layout

Global styles are located in:

`app/globals.css`

Some components may also contain their own styles.

Use the following guide:

- Global colours, typography and shared styles:
  `app/globals.css`

- Header and navigation appearance:
  `components/site-header.tsx` and its related CSS rules.

- Footer appearance:
  `components/site-footer.tsx` and its related CSS rules.

- Homepage section appearance:
  `app/page.tsx` and its related CSS rules.

### Important

The stylesheet may contain multiple rules for the same section because the
design has been updated over time.

Before changing a colour, button, hero image or layout:

1. Identify the exact element.
2. Find all relevant CSS selectors.
3. Check whether later rules override earlier rules.
4. Make a targeted change.
5. Test at desktop and mobile widths.

Avoid repeatedly appending conflicting CSS overrides. This can make the
website difficult to maintain.

## 9. Running the Website on a Computer

You need Node.js and npm installed.

On macOS, open Terminal and navigate to the project folder:

    cd "$HOME/Desktop/kushal-site-update/kushal-tours-website"

Install the project dependencies:

    npm install

Start the local development server:

    npm run dev

Open this address in your browser:

    http://localhost:3000

Keep the Terminal window open while using the local development server.

To stop it, return to Terminal and press `Control + C`.

The local address is only for testing on your computer. It is not the public
website address.

## 10. Checking Before Publishing

After making changes, check the website locally.

Verify:

- The homepage loads.
- The header and footer display correctly.
- All main pages open.
- Images load and are cropped correctly.
- Text is readable on the hero image.
- Call buttons open the correct telephone number.
- WhatsApp links open the intended contact.
- Navigation links point to the correct pages or sections.
- The layout works on both desktop and mobile.
- No unrelated section has been broken.

Run the production build:

    npm run build

If the build fails, read the error and fix it before publishing.

A successful build checks whether the project can compile. It does not
guarantee that every visual detail or every link is correct, so manual
testing is still necessary.

## 11. GitHub — Keeping the Project Online

GitHub stores the project's source code and change history.

The usual workflow is:

1. Open or create the correct GitHub repository.
2. Upload the project source code.
3. Ensure private configuration and secrets are not uploaded.
4. Confirm the repository contains the necessary source files and lockfile.
5. Connect the repository to Vercel.

Do not upload generated folders such as `node_modules/` or `.next/`.

sensitive configuration are excluded.

creating a duplicate unnecessarily.

## 12. Vercel — Publishing the Website

Vercel builds and hosts the website.

The normal deployment workflow is:

1. Sign in to Vercel.
2. Import the correct GitHub repository.
3. Select the correct project settings.
4. Deploy the website.
5. Open the generated Vercel URL.
6. Test the published website.
7. Connect the purchased custom domain after the initial deployment works.

When the GitHub repository is connected to Vercel, new commits can trigger
new deployments automatically.

Do not assume that a local change is already live. Confirm that the latest
deployment completed successfully and check the public website.

## 13. Connecting the GoDaddy .in Domain

The custom `.in` domain is managed through GoDaddy, while the website can
be hosted by Vercel.

These are separate services.

### Recommended order

1. Upload the project to the correct GitHub repository.
2. Import that repository into Vercel.
3. Deploy and test the website using its Vercel-provided address.
4. Open the project in Vercel.
5. Find the project's Domains settings.
6. Add the exact purchased `.in` domain.
7. Follow the DNS records Vercel displays for that domain.
8. Open GoDaddy and find the domain's DNS management page.
9. Add or update the DNS records exactly as instructed by Vercel.
10. Return to Vercel and wait for domain verification.
11. Test the custom domain in a browser.

Vercel's displayed DNS instructions are the source of truth for the records
required by the current project configuration. Do not copy DNS values from
an unrelated tutorial or another website.

Avoid deleting unrelated DNS records, particularly email-related records,
without checking what they are used for.

DNS updates can take time to propagate. A domain may not work immediately
after changing its records.

Once configured, decide which domain should be the primary address and
check whether the other version redirects correctly.

## 14. Troubleshooting

### The website does not start locally

- Confirm that Node.js and npm are installed.
- Run `npm install`.
- Read the full Terminal error.
- Confirm that you are inside the project directory.

### A change is visible locally but not online

- Confirm that the latest source changes were saved.
- Confirm that the correct GitHub repository received the changes.
- Check the latest Vercel deployment status.
- Confirm that you are opening the correct production domain.
- Refresh the page and check again.

### An image does not appear

- Check that the image exists in `public/`.
- Check the spelling, filename and file extension.
- Check the path used by the component.
- Check the browser console and build output for errors.

### A call button uses the wrong number

- Check the shared settings in `lib/site.ts`.
- Search for hardcoded telephone numbers in the project.
- Check telephone links and WhatsApp links separately.
- Test the final deployed website.

### The custom domain does not open

- Check that the domain was added to the correct Vercel project.
- Check the DNS records against the instructions shown by Vercel.
- Check the domain verification status.
- Allow time for DNS propagation.
